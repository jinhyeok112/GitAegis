# GitAegis

**GitHub 저장소의 소스 코드와 의존성을 분석하는 AI 보안 취약점 진단 SaaS**

GitAegis는 저장소별 보안 위험을 웹 대시보드에 모아, **어느 저장소의 어느 코드가 왜 위험한지** 확인할 수 있도록 돕는 심화응용프로젝트이다. 소스 코드의 보안 결함을 탐지하는 SAST와 의존성 패키지의 알려진 취약점 검사를 결합하고, AI로 문제 설명과 수정 방향을 제공하는 것을 목표로 한다.

> 현재는 프론트엔드 프로토타입과 DB 설계를 준비하는 단계이다. 대시보드·취약점 상세·계정 화면, 타입이 지정된 가상 데이터, MySQL 스키마 초안을 마련했다. AI 수정 제안과 수정 전·후 코드는 준비된 예시 데이터로 보여준다. 실제 GitHub 인증, 보안 분석, AI 호출, 결제는 아직 구현하지 않았다.

## 프로젝트 개요

GitHub 저장소를 연동한 뒤 커밋 발생 시와 사용자가 설정한 정기 일정에 보안 검사를 수행하는 서비스를 계획한다. 사용자는 검사 결과의 위험도, 파일 경로, 코드 위치, 문제 설명을 확인하고 높은 위험의 취약점부터 검토할 수 있다.

## 최종 서비스의 주요 기능

| 기능 | 계획한 동작 |
| --- | --- |
| GitHub 로그인 | GitHub OAuth로 인증하고 읽기 권한으로 저장소 목록 조회 |
| 저장소 연결 | 유료 계정으로 GitHub 저장소를 선택하고 검사 대상으로 등록 |
| 소스 코드 검사 | Semgrep 엔진으로 SAST 수행 |
| 의존성 취약점 검사 | OSV.dev로 알려진 취약점과 CVE 정보 확인 |
| 자동 스캔 | 저장소별 커밋 검사 및 매일·매주 정기 분석 설정 |
| 결과 저장 | 발견한 문제와 위험도, 검사 결과를 데이터베이스에 저장 |
| 보안 현황 확인 | 대시보드와 취약점 목록에서 저장소별 위험 확인 |
| 취약점 상세 확인 | 결함 설명, 영향, 파일 경로, 문제 코드 구간 표시 |
| AI 분석 지원 | 탐지 결과를 바탕으로 문제 설명과 수정 위치·코드 제안 |
| 스캔 기록 | 검사 시각, 실행 방식, SAST·의존성 취약점 건수, 상태 조회 |
| 계정 및 결제 | 구독 계정과 사용량을 관리하고 AI 분석 사용량에 따른 추가 요금을 안내 |

SAST는 소스 코드를 실행하지 않고 보안 결함을 찾는 정적 분석이다. 의존성 취약점 검사는 사용하는 패키지에 알려진 보안 문제가 있는지 확인한다. AI 분석은 탐지 결과의 이해와 수정을 돕는 후속 단계로 계획한다.

## 현재 개발 단계

현재 단계의 목표는 **백엔드 없이 Dummy/Mock Data로 전체 UI와 주요 사용자 흐름을 확인할 수 있는 프론트엔드 목업과 DB 설계를 준비하는 것**이다. 현재 주요 화면과 상호작용, 공통 데이터 타입 및 가상 데이터, MySQL 스키마 초안을 마련했다.

### 이번 단계의 구현 범위

- GitHub 로그인 화면과 모의 로그인 흐름
- 대시보드, 저장소 연결, 분석 설정, 취약점 목록·상세, 스캔 기록
- 화면 간 이동과 공통 메뉴
- 저장소 검색 및 모의 연결·해제
- 저장소별·종류별 취약점 필터
- Dummy/Mock Data를 이용한 보안 현황과 검사 결과 표시
- 취약점별 AI 해결 방법·변경점·수정 전후 코드 예시
- 유료 계정 상태 및 AI 분석 사용량·과금 방식 안내 화면

### 이후 단계의 구현 범위

- 실제 GitHub OAuth 및 GitHub API 연동
- Backend API와 데이터베이스
- 실제 Repository Clone과 Semgrep 실행
- OSV.dev 연동 및 실제 CVE/SAST 분석
- 커밋 이벤트 처리와 정기 스캔 실행
- Gemini를 통한 AI 설명 및 수정 제안
- OCI 배포 환경 구성

이번 단계의 로그인, 저장소 연결, 취약점 및 스캔 결과는 모두 모의 동작과 예시 데이터로 구성한다.

## 화면 구성

화면설계 자료를 바탕으로 주요 흐름을 구성한다. 대시보드는 저장소별 최근 취약점과 검사 활동에 집중하고, 스캔 기록은 계정 및 사용량 화면에 모은다.

| 화면 | 표시 내용 및 주요 동작 |
| --- | --- |
| GitHub 로그인 | 서비스 소개, GitHub로 계속하기 버튼, 저장소 읽기 권한 안내 |
| 저장소 설정 | 저장소 검색, 공개·비공개 여부, 연결 상태, 가져오기 및 연결 해제 |
| 분석 설정 | 연결된 저장소별 커밋 검사, 정기 분석 사용 여부, 매일·매주 일정과 시각 설정 목업 |
| 대시보드 | 확인할 코드·패키지·진행 중인 검사, 저장소명이 표시된 최근 취약점, 검사 수 선 그래프와 취약점 탐지 건수 막대 그래프 |
| 취약점 목록 | 위험도, 결함 이름, 저장소, 파일 경로, 저장소·종류 필터 |
| 취약점 상세 | 결함 설명, 영향, 파일·패키지와 버전, AI 해결 방법·변경점·수정 전후 코드 목업 |
| 스캔 기록 (계정 화면 내) | 실행 시각, 저장소 선택, 커밋·정기 실행 구분, SAST·CVE 건수, 처리 상태 |
| 계정 및 사용량 | GitHub 계정 연결 상태, 유료 계정, AI 사용량 및 과금 안내, 스캔 기록, 로그아웃 |

화면은 흑백 중심으로 구성하며, 로그인 이후에는 공통 메뉴를 통해 주요 화면을 이동한다. 화면설계에 등장하는 일반 설정 메뉴의 세부 기능은 이번 목업의 필수 범위에 포함하지 않는다.
취약점과 스캔 기록의 저장소 선택 목록에는 현재 연결된 저장소를 먼저, 연결 해제 후 기록이 남은 저장소를 그다음에 표시한다. 한 번도 연결하지 않아 기록이 없는 저장소는 표시하지 않는다.

### 사용자 흐름

1. 로그인 화면에서 모의 로그인 후 대시보드로 이동한다.
2. 저장소 설정에서 분석할 예시 저장소를 검색하고 연결한다.
3. 분석 설정에서 저장소별 커밋 검사와 정기 분석 일정을 설정한다.
4. 대시보드에서 확인할 항목과 저장소명이 포함된 최근 취약점을 보고 검사·탐지 건수의 변화를 비교한다.
5. 취약점 목록에서 저장소와 종류로 결과를 좁힌다.
6. 취약점을 선택해 설명, 영향, 코드 위치 또는 패키지 버전과 AI 수정 전후 코드 예시를 확인한다.
7. 계정 및 사용량에서 GitHub 연결 상태와 AI 사용량을 확인하고 스캔 기록을 조회한다.

실제 서비스에서는 저장소 연결 이후 자동 검사를 수행하도록 계획한다. 목업에서는 준비된 검사 결과로 이 흐름을 재현한다.
분석 설정 화면은 선택한 저장소의 예시 설정만 현재 화면에 반영한다. 실제 예약 실행, 새 스캔 기록 생성 및 새로고침 후 설정 보존은 백엔드 연동 단계에서 구현한다.

### 계정 및 과금 방향

- 서비스는 유료 계정 중심의 구독형 모델로 기획한다. 무료 등급이나 무료 계정의 저장소 개수 제한은 두지 않는다.
- 기본 수입원은 개인·팀용 구독료이며, 저장소 연결과 기본 보안 검사 기능을 유료 계정에 제공한다.
- AI 설명 및 수정 제안은 사용량에 따라 추가 과금하는 방안을 검토한다. 계정 화면과 요금 안내에는 사용량과 예상 추가 비용을 표시하는 방향으로 설계한다.
- AI 사용 단위, 요율, 월 구독 가격은 아직 정하지 않았다. 목업에 금액을 표시할 경우 실제 확정 요금이 아닌 예시임을 분명히 밝힌다.
- `sample-shopping-api`, `demo-community-web` 등의 저장소명, 파일 경로, 검사 시각, 건수는 가상 데이터이다.
- 화면설계의 `CVE-2026-1234`는 예시 식별자이며 실제 취약점 정보를 의미하지 않는다.

## 기술 구성 계획

| 영역 | 기술 | 용도 |
| --- | --- | --- |
| 프론트엔드 | Next.js, TypeScript, Tailwind CSS | 웹 화면과 사용자 상호작용 |
| 백엔드 | Python, FastAPI | 인증 연동, 검사 요청 및 결과 제공 |
| 인증·저장소 연동 | GitHub OAuth, GitHub API | 로그인과 저장소 조회 |
| 정적 분석 | Semgrep 엔진 | 소스 코드 보안 결함 탐지 |
| 의존성 분석 | OSV.dev | 패키지의 알려진 취약점 조회 |
| AI | Gemini | 탐지 결과 설명 및 수정 제안 |
| 데이터베이스 | MySQL | 저장소, 취약점, 스캔 결과 저장 |
| 운영 환경 | Oracle Cloud Infrastructure(OCI) | 백엔드 서버 운영 |

현재 프론트엔드 기반은 Next.js App Router, TypeScript, Tailwind CSS로 구성했다. 패키지 버전은 `package-lock.json`에 고정한다.

Next.js·Tailwind CSS·FastAPI는 개략제안서, TypeScript·Semgrep·OSV.dev·MySQL·OCI·Gemini는 상세제안서의 기술 계획을 반영했다. 구체적인 버전, API 명세, 배포 방식은 구현 단계에서 정한다.

### 서비스 처리 구조

```text
사용자 → 웹 프론트엔드 → 백엔드 API
                           ├─ GitHub 인증 및 저장소 조회
                           ├─ 커밋 이벤트 / 일 단위 정기 스캔
                           │    ├─ Semgrep: 소스 코드 검사
                           │    └─ OSV.dev: 의존성 취약점 조회
                           ├─ Gemini: 설명 및 수정 제안
                           └─ MySQL: 검사 결과 저장

저장한 결과 → 대시보드 / 취약점 목록·상세 / 스캔 기록
```

위 구조는 최종 서비스의 계획이다. 현재 목업은 프론트엔드와 Mock Data만 사용한다.

## 목업 데이터 구조

기존 README의 세 가지 모델을 기준으로 화면에 필요한 데이터를 준비한다. `lib/types.ts`와 `lib/mock-data.ts`는 프론트엔드 목업용 타입과 가상 데이터다. 실제 데이터베이스 초안은 `database/schema.sql`의 MySQL 8 스키마에서 별도로 관리한다.

| 필드 | 의미 |

| `id` | 저장소 식별자 |

### 상용 서비스용 계정·과금 데이터 계획

다음 항목은 상용 서비스 방향을 반영한 추가 설계 후보이다. 구체적인 요금과 결제 사업자는 아직 정하지 않았다.

| 테이블 | 저장할 내용 |
| --- | --- |
| `users` | 계정과 GitHub 사용자 식별 정보 |
| `subscriptions` | 구독 플랜, 구독 상태, 시작일·갱신일 |
| `ai_usage_records` | AI 기능 종류, 사용량, 사용 시각, 계산된 예상 비용 |
| `invoices` | 청구 기간, 기본 구독료, AI 사용 요금, 총액, 결제 상태 |

AI 사용량과 예상 비용을 기록해 계정 화면과 청구 내역에서 확인할 수 있도록 설계한다. 실제 청구 전에 사용량 단위, 요율, 부가세 및 결제 정책을 확정해야 한다. 목업의 요금은 확정 가격처럼 표현하지 않는다.

`Vulnerability.repositoryId`와 `Scan.repositoryId`는 `Repository.id`를 참조한다. 대시보드의 위험도별 건수는 같은 취약점 데이터에서 집계하고, 최근 검사 시각은 스캔 기록과 일치시킨다. 의존성 검사 결과에 소스 코드 행 정보가 없으면 상세 화면에서 해당 항목을 생략한다.

DB 초안은 계정, 구독, 저장소, 검사, 취약점, 검사별 발견 결과, 취약점 상태 변경 이력, AI 사용량, 청구서 테이블로 구성한다. 검사별 발견 결과와 취약점의 지문을 분리해 반복 검사에서 같은 문제를 연결하고, 신규·유지·해결 변화를 추적하는 방향이다. AI 사용량과 예상 비용을 기록하되 요율과 실제 구독 가격은 미정이다. 현재 스키마는 설계 검토용이며 실행 마이그레이션이 아니다.
`repositories`에는 커밋 검사 여부와 정기 분석의 주기·요일·시각·시간대를 기록한다. `next_scheduled_at`은 실제 스케줄러 연동 시 계산해 갱신할 필드이며, 현재 목업에서는 예약 작업을 만들지 않는다.

## DB 설계 검토 화면 (임시)

사이트의 `DB 설계 · 검토용` 메뉴에서 교수님 검토용 ERD를 확인할 수 있다. 메인 흐름은 저장소 → 검사 → 발견 내역 → 취약점 순서로 배치하며, 상태 이력·AI 사용량은 별도 서브 흐름으로 보여준다. 계정·구독·청구는 작은 접이식 영역에서 확인한다. 테이블 선택 시 연결된 테이블의 테두리가 강조되며 전체 컬럼, NULL 허용 여부, PK/FK, 인덱스와 제약을 확인할 수 있다. SQL 원문 보기와 다운로드도 제공한다. 화면은 `database/schema.sql`에서 직접 읽어 생성하며 실제 DB에 연결하거나 데이터를 저장하지 않는다.

임시 메뉴는 `components/dashboard.tsx`의 `menu` 배열에 있는 `database` 항목을 제거하면 숨길 수 있다. 완전히 제거할 때는 해당 뷰와 컴포넌트, `app/page.tsx`의 설계 데이터 전달도 함께 제거한다. 기존 SQL 초안의 미확정 사항(AI 응답 저장, 구독 변경 이력, 청구 집계 연결, 보존 정책)은 화면 하단에 표시한다.

### CVE / CWE 연동 계획

**CVE 데이터 조회는 NIST NVD API 2.0을 이용할 계획이다.** 현재 사이트는 더미 데이터로 동작하며 API를 실제 호출하지 않는다.

- **CVE 상세 조회:** [NVD CVE API](https://nvd.nist.gov/developers/vulnerabilities)의 `GET https://services.nvd.nist.gov/rest/json/cves/2.0?cveId=CVE-2021-23337`로 설명, CVSS, 영향 제품·버전 조건 및 제공된 CWE 분류를 확인한다.
- **패키지 버전 대조:** lock 파일에서 패키지명·설치 버전을 추출하고 [NVD CPE API](https://nvd.nist.gov/developers/products)의 제품 식별자와 매핑한 뒤 영향 조건을 대조한다. 이름 검색만으로 취약 여부를 확정하지 않는다. 매핑 불확실·정보 누락은 확인 필요로 표시한다.
- **최소 수정 버전:** NVD 참고 링크의 패키지 공식 보안 공지·릴리스에서 버전 계열별로 확인한다. NVD가 모든 패키지의 수정 버전을 별도 필드로 제공한다고 가정하지 않으며, 근거가 없으면 미확인으로 표시한다.
- **코드 약점 탐지:** Semgrep 검사 결과와 [규칙 메타데이터](https://github.com/semgrep/semgrep-rules/blob/develop/metadata-schema.yaml.schm)의 CWE를 사용한다. CWE는 약점 유형이며 API 자체로 코드를 검사하지 않는다.
- **CWE 설명 조회:** [MITRE CWE REST API](https://github.com/CWE-CAPEC/REST-API-wg/blob/main/Quick%20Start.md)의 `GET https://cwe-api.mitre.org/api/v1/cwe/weakness/79` 등으로 약점 설명을 가져온다. 등록·인증 없이 조회 가능하며 XML/CSV 다운로드도 대안이다.

외부 조회는 백엔드에서 수행하고 캐시·재시도·조회 시각을 관리할 계획이다. 현재 SQL은 패키지 버전 및 advisory URL을 저장하지만, CPE 매핑과 복수 CWE 분류, 원본 응답·조회 시각은 별도 구조를 보완해야 한다. 이 연동 계획은 DB 검토 화면에서도 확인할 수 있다.
