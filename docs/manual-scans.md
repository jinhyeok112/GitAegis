# 수동 검사와 결과 저장

## 사용

저장소 메뉴에서 저장소를 연결한 뒤 `수동 검사`를 누른다. 완료 안내에 탐지 건수와 커밋 SHA가 표시된다. 취약점 메뉴에서 코드 위치·설명·등급을 확인하고, 계정 및 사용량의 검사 기록에서 성공·실패와 실패 사유를 확인한다.

검사 대상은 **GitHub에 올라간 기본 브랜치의 특정 커밋**이다. 로컬의 미커밋·미푸시 변경은 포함하지 않는다. 안전 샘플도 원격에 반영한 뒤 검사해야 한다. 샘플 탐지는 문제 유형을 제목에 표시하고 `정보` 등급과 내부 샘플 메타데이터를 유지한다.

JavaScript·TypeScript·Python의 제한된 SAST 규칙을 실행한다. 일반 규칙은 동적 eval, TLS 검증 해제, Python 셸 실행·SQL 결합을 검토 대상으로 표시하며 전용 샘플 규칙 5개도 포함한다. 탐지는 Semgrep이 담당한다. 외부 입력의 실제 도달 가능성·영향은 사람이 검토한다. 탐지 0건은 전체 취약점이 없다는 판정이 아니다.

`package-lock.json` 또는 `npm-shrinkwrap.json`(v2/v3)이 있으면 npm의 직접·전이 의존성 이름과 설치 버전을 OSV에 조회한다. 실행·설치 스크립트는 사용하지 않는다. 지원 잠금 파일이 없으면 의존성 칸은 `미실행`이다. Yarn·pnpm·PyPI 등 다른 형식은 아직 검사하지 않는다. 잠금 파일이 잘못됐거나 npm 외부 소스가 포함되거나 조회를 완료하지 못하면 전체 검사를 실패로 기록하고 기존 결과를 유지한다.

상세 화면의 `AI 수정안 생성`은 Semgrep 규칙·설명·영향과 저장된 코드 조각만 사용자가 선택한 Gemini 또는 OpenRouter 모델에 전송한다. AI가 저장소를 분석하거나 새 문제를 탐지하지 않는다. 제안은 적용·실행하지 않고 같은 검사 위치에 저장한다.

분석 설정의 **AI 수정안 모델**에서 제공자·모델을 선택하면 `user_ai_settings`에 로그인한 `user_id`별로 저장한다. 설정 API는 `GET/PUT /api/ai/settings`이며 요청에 넣은 사용자 ID는 사용하지 않는다. 저장 전에는 서버 `OPENROUTER_MODEL` 또는 기본 `nvidia/nemotron-3-ultra-550b-a55b:free`를 사용한다. OpenRouter 목록은 공개 모델 API의 텍스트 입출력·가격 0인 무료 모델을 15분 캐시해 표시한다. 목록 조회 실패 시 무료 자동 라우터만 선택 가능하며, 유료·이미지 전용·알 수 없는 모델은 저장을 거절한다.

API 키는 서버의 `OPENROUTER_API_KEY`와 `GEMINI_API_KEY`를 사용한다. 키가 없는 제공자는 선택 목록에 연결 필요로 표시하며 키 자체를 응답하지 않는다. 모델 설정은 계정별이지만 제공자 호출 한도는 서버 API 계정·프로젝트의 한도를 공유한다. OpenRouter는 가격 상한을 0으로 보내 유료 경로를 차단한다. Gemini는 공식 무료 티어 대상 텍스트 모델만 허용하지만, **API 프로젝트에 결제가 연결되어 있으면 사용량이 과금될 수 있다.** Google AI Plus/Pro 구독과 API 요금제는 별개이며, 무료 운영에는 Free 티어 프로젝트의 키를 사용해야 한다. Gemini 비용은 무료라고 단정해 0으로 기록하지 않고 미산정(NULL)으로 저장한다. 무료 제공자의 데이터 이용 조건도 확인해야 한다.

수정안에는 선택한 제공자·모델을 기록한다. 같은 검사·같은 모델의 결과는 재사용하고 모델이 변경되면 새로 생성한다. 생성 실패 시 이전 수정안은 보존한다. 의존성 결과도 선택 모델이 달라지면 캐시를 재사용하지 않는다. 모델 변경이 Semgrep 탐지나 기존 취약점 상태를 바꾸지는 않는다.

## 요청과 코드 구조

의존성 상세의 `업데이트 버전 확인`은 다음 순서로 실행한다.

1. OSV에서 현재 버전의 모든 공지를 다시 조회하고 해당 패키지의 `ranges.events.fixed`를 수정 버전 후보로 수집한다. 같은 CVE의 별칭으로 연결된 공지도 확인한다.
2. CVE가 있으면 NVD 2.0 API에서 설명·참고 링크·제공된 affected 데이터를 보완한다. NVD에는 모든 패키지에 공통된 `fixedVersion` 필드가 없다. CPE의 `versionEndIncluding`에 임의로 1을 더하거나 `versionEndExcluding`을 전체 버전의 안전 기준으로 쓰지 않는다.
3. 해당 공지에 명시된 수정 버전이 없으면 사용자가 선택한 AI 모델이 공급된 공지·NVD 정보에서 후보와 근거를 추출한다. 근거가 없으면 미확인으로 남긴다. 링크 URL만 보고 문서 내용을 읽었다고 취급하지 않는다.
4. npm 레지스트리에 배포된 버전 중 설치 버전보다 높은 정식 `x.y.z` 버전을 숫자 순서로 확인한다. 시험판과 deprecated 버전은 제외한다. 모든 앞선 후보를 OSV에 정확한 패키지·버전으로 조회하고, 기존 CVE 외의 취약점도 하나라도 있으면 건너뛴다. 첫 미탐지 버전 하나만 권장한다. AI 후보도 이 검증을 우회할 수 없다.
5. 조회 실패·불완전한 페이지·후보 1,000개 한도 초과는 미검증이다. 조회 시각·출처·제외된 앞선 후보(최대 20개)를 저장한다. 의존성 결과는 1시간 재사용하고 NVD 원문 근거는 24시간 캐시한다.

**검증 범위:** 조회 시점 OSV에 알려진 해당 패키지 자체의 취약점이다. 이후 버전 전체, 아직 공개되지 않은 취약점, 플랫폼별 실행 호환성은 보장하지 않는다. 업데이트로 바뀌는 전이 의존성은 새 잠금 파일을 만든 후 다시 수동 검사해야 한다. 파일을 자동으로 변경하거나 의존성을 설치하지 않는다. 업데이트 적용 후 빌드·테스트가 필요하다.

NVD는 API 키 없이 이용하며 공개 한도인 **30초당 5회**에 맞춰 요청 사이를 6.1초 이상 띄운다. MySQL 잠금과 요청 시각을 함께 저장해 같은 DB를 쓰는 여러 워커·재시작에서도 간격을 유지한다. 같은 외부 IP를 공유하는 별도 애플리케이션까지 제어하지는 못한다. 403/429는 Retry-After를 지켜 한 번 재시도하고 NVD 조회 실패는 화면에 표시한다. OSV는 별도의 패키지 버전 데이터 출처이며 NVD 조회 성공과 혼동하지 않는다.

출처: [NVD 개발 가이드](https://nvd.nist.gov/developers/start-here), [NVD 응답 스키마](https://csrc.nist.gov/schema/nvd/api/2.0/cve_api_json_2.0.schema), [OSV 스키마](https://ossf.github.io/osv-schema/), [OSV 배치 조회·페이지 처리](https://google.github.io/osv.dev/post-v1-querybatch/).

추가 테이블 `finding_remediations`, `security_api_cache`, `user_ai_settings`는 `npm run db:init`으로 생성한다. 기존 기록은 보존한다. AI 사용 모델·토큰은 `ai_usage_records`에 기록하며 제안을 생성했다고 취약점을 해결 상태로 변경하지 않는다.

```text
수동 검사 버튼
  → POST /api/repositories/[id]/scans
  → 로그인·요청 출처·소유권·연결 상태 검증
  → DB 실행 잠금과 running 이력 생성
  → GitHub 접근 권한 재확인 → 기본 브랜치 SHA → 소스 압축 다운로드
  → Python 소스 추출 → Semgrep 정적 분석
  → 지원 npm 잠금 파일이 있으면 OSV로 설치 버전 조회
  → 트랜잭션으로 취약점·코드 위치·완료 이력 저장
  → 화면 데이터 갱신 및 임시 소스 삭제
```

`app/api/repositories/[id]/scans/route.ts`는 서버 전용 진입점이다. 요청에서 명령·경로·사용자 ID를 받지 않는다. 세션으로 소유자를 결정하고 다른 사용자 저장소와 교차 사이트 요청을 거절한다.

`lib/server/manual-scan.ts`는 MySQL의 `GET_LOCK`을 연결에 유지한다. DB당 수동 검사를 한 번에 하나만 허용하고 중복 요청은 409로 거절한다. 잠금을 얻은 새 작업은 서버 중단으로 남은 `running` 이력을 실패로 바꾼다. 새 검사는 별도의 UUID를 가진다. 화면은 실행 중 주기적으로 상태를 갱신하고, 재시작으로 멈춘 이력이 남아도 수동 검사 재시도로 복구할 수 있다.

`lib/server/github.ts`는 저장된 토큰으로 접근 권한을 다시 확인한다. 기본 브랜치의 SHA를 확정한 뒤 그 SHA의 압축 파일을 요청하므로 도중에 브랜치가 바뀌어도 검사 버전을 식별할 수 있다. GitHub의 다운로드 리다이렉트는 HTTPS `codeload.github.com`만 허용하고 OAuth 토큰을 넘기지 않는다. 토큰·압축 주소를 브라우저에 전달하지 않는다.

`scripts/extract_scan_source.py`는 저장소의 JS·TS·Python 일반 파일만 새 임시 폴더에 복사한다. 경로 이탈·절대 경로·링크·장치·중복 경로를 거절하고 의존성·빌드 폴더는 제외한다. 저장소의 설치 스크립트나 프로그램은 실행하지 않는다.

`lib/server/scan-engine.ts`는 `spawn`의 인수 배열과 `shell:false`로 Python·Semgrep을 실행한다. 자식 프로세스에는 OAuth·MySQL 비밀값을 전달하지 않는다. 규칙은 서버의 `security_rules/manual.yaml`과 `security_fixtures/cases.yaml`만 사용한다. 저장소에 포함된 규칙·설정은 로드하지 않는다. 결과의 경로·위치·개수·크기·분석 오류를 확인하고 원본 소스에서 코드 조각을 읽는다.

제목은 신뢰된 규칙의 `metadata.gitaegis_title`을 우선 사용해 `입력값으로 서버 명령 실행 가능(CWE-78)`처럼 어떤 위험인지 드러나는 짧은 문장으로 표시한다. 제목 메타데이터가 없으면 Semgrep의 `message`를 사용한다. `metadata.gitaegis_impact`에는 피해 가능성, `metadata.gitaegis_description`에는 해결 방법을 쉬운 문장으로 작성한다. 화면은 두 내용을 **문제와 해결 방법**으로 묶어 피해 가능성 → 해결 방법 순으로 표시한다. 매번 AI로 문구를 다시 작성하지 않는다. 설명 메타데이터가 없는 규칙은 Semgrep 문장으로 대체하며, 영향 근거가 없으면 미등록 안내를 표시한다. 샘플은 내부 메타데이터로 구분하고 화면에 실제 CVSS와 다른 샘플 검증용 점수임을 안내한다.

규칙 문구를 바꾼 뒤 기존 DB에도 적용하려면 `npm run db:sync-rule-copy`를 실행한다. 서버의 신뢰하는 규칙 ID와 일치하는 SAST 항목의 제목·설명·영향만 갱신하며 검사 이력·코드·취약점 상태는 유지하고, 신뢰된 규칙의 등급과 샘플 점수도 갱신한다. Semgrep 가상환경의 Python·ruamel.yaml과 DB 연결 설정이 필요하다. 재검사에서도 기존 항목의 영향 설명을 갱신한다.

## DB 설계

| 테이블 | 저장 내용 |
| --- | --- |
| `scans` | 저장소, manual 실행, SHA, 상태, 시작·완료 시각, SAST 건수, 실패 메시지, scan_scope |
| `vulnerabilities` | 저장소별 규칙·제목·등급·설명·영향·상태·최초/최근 탐지 시각 |
| `scan_findings` | 검사와 취약점의 연결, 파일 경로·시작/끝 줄·코드 조각 |

`scan_scope=sast`는 의존성 검사를 수행하지 않았음을 구분한다. `npm run db:init`은 기존 데이터에 손대지 않고 이 열이 없을 때 추가한다. 기존 기록의 범위는 `unknown`이다.

취약점의 fingerprint는 **규칙 ID + 파일 경로 + 시작 줄 + 코드**의 SHA-256이다. 같은 위치·코드를 다시 탐지하면 기존 취약점을 갱신하고 새 검사와 연결한다. `resolved`는 재발견 시 `open`으로 바꾸지만 오탐·위험 수용 상태는 유지한다. 줄이나 코드가 달라지면 별도 항목이 될 수 있다. 이번 검사에서 발견되지 않은 과거 항목을 자동 해결 처리하지 않는다.

분석 성공 후 결과 삽입과 완료 처리를 하나의 DB 트랜잭션으로 커밋한다. 실패하면 결과 저장을 롤백하고 검사 이력만 실패로 남긴다. 이전 결과를 삭제하거나 실패를 0건 성공으로 표시하지 않는다. 임시 폴더는 이번 호출에서 만든 `.tools/scans/run-*`인지 확인한 후 삭제한다.

## 실행 한도

| 항목 | 한도 |
| --- | --- |
| 압축 다운로드 | 25MB, 30초 |
| 압축 전체 파일 크기 합 | 100MB |
| 압축 항목 수 / 검사 소스 수 | 15,000 / 3,000 |
| 소스 한 파일 | 1MB |
| 압축 해제 / Semgrep 전체 시간 | 20초 / 90초 |
| Semgrep 작업 수 / 파일별 시간 / 메모리 옵션 | 1 / 5초 / 512MB |
| 결과 | 1,000건, JSON 16MB |

지원 파일이 없거나 분석 오류·한도 초과가 발생하면 실패로 남긴다. 일부만 분석한 결과를 전체 완료로 표시하지 않는다. Semgrep의 메모리 옵션은 OS 전체 자원 격리를 대신하지 않는다.

## 다른 PC와 OCI

현재 PC는 `.tools/semgrep` 가상환경을 준비했다. 이 폴더는 Git에 포함하지 않으므로 이전할 서버에서 별도로 설치한다. 검증에 사용한 Semgrep 버전은 1.181.0이다.

```bash
python -m venv .tools/semgrep
# Windows
.tools/semgrep/Scripts/python.exe -m pip install semgrep==1.181.0
# Linux: 위 설치 명령 대신
.tools/semgrep/bin/python -m pip install semgrep==1.181.0
```

기본 경로는 Windows의 `Scripts`, Linux의 `bin`을 자동 선택한다. 다른 위치에 설치하면 `.env.local`의 `SEMGREP_EXECUTABLE`, `SCAN_PYTHON_EXECUTABLE`에 실행 파일 절대 경로를 지정한다. 서버 사용자에게 실행 권한과 `.tools/scans` 쓰기 권한이 필요하다. 배포에는 `scripts/extract_scan_source.py`, `security_rules/manual.yaml`, `security_fixtures/cases.yaml`도 포함한다. OCI ARM64에서 설치·실행 검증은 별도로 필요하다.

현재 검사는 POST 요청 동안 동기 실행한다. Next 경로의 `maxDuration`은 180초이며 운영 프록시의 요청 제한도 이에 맞춰야 한다. 서버 중단은 진행 중 검사를 멈출 수 있다. 푸시·정기 자동 검사는 후속 구현 범위다. 수정안 생성은 아래의 별도 백그라운드 대기열을 사용한다.

## 검증

`npm run test:data`는 격리된 임시 MySQL DB와 테스트 전용 GitHub 압축 응답으로 **실제 Semgrep**을 실행한다. 샘플 7건+일반 규칙 1건, SHA·코드 저장, 재검사 중복 방지, 실행 잠금, 서버 중단 이력 복구, 잘못된 압축의 실패 기록과 npm·AI 수정안 저장을 확인한다. 사용자별 모델 격리·재시작 후 설정 유지·유료 모델 거절·Gemini/OpenRouter 실제 선택 경로와 모델 변경 후 캐시 갱신도 검증한다. 외부 API는 모의 응답을 사용한다. 실제 사용자 DB나 실제 API 키는 테스트에 사용하지 않는다.

`npm run test:remediation`은 기존 취약점 수정 버전에 다른 취약점이 있는 경우, AI의 존재하지 않는 버전 제안, OSV 페이지 처리·오류, NVD 요청 간격·캐시·재시도, 무료 모델 강제와 불완전한 AI 응답 거절을 검증한다.

`npm run test:scan-safety`는 압축 경로 이탈·링크·중복·용량·지원 파일 조건을 검증한다. `npm run test:fixtures`는 샘플 자체에 외부 시스템 동작이 없는지 확인한다.


## 자동 수정안 생성과 코드 비교

검사 결과를 저장하는 트랜잭션 안에서 7.0 이상인 모든 미해결 항목을 `remediation_jobs`에 추가한다. 3개 같은 개수 제한은 없다. 출처의 숫자 점수가 없으면 높은 위험도·치명적 등급으로 판단하며 등급을 임의의 CVSS 점수로 바꾸지 않는다. 해결·오탐·위험 수용 항목은 사전 생성하지 않는다.

나머지는 세부정보가 열릴 때 POST로 작업을 등록한다. POST는 생성을 기다리지 않고 202와 상태를 반환한다. GET은 소유자를 확인한 후 상태와 저장된 결과만 읽는다. 화면은 기존 정보를 즉시 표시하고 수정안 영역만 준비 상태로 표시하며 2.5초 간격으로 상태를 확인한다. 화면을 닫아도 작업은 유지된다. 실패 시 자동으로 반복 호출하지 않고 다시 시도 버튼을 제공한다.

`instrumentation.ts`가 지속 실행되는 Node 서버에서 작업자를 시작한다. DB 이름별 MySQL 잠금으로 여러 서버의 중복 처리를 방지한다. DB에 저장한 작업은 프로세스 재시작 후 복구한다. 작업은 하나씩 처리하고 시작 간격은 최소 3.5초, 실패 후 다음 작업까지 60초를 두며, 무료 한도를 우회하지 않는다. 중단된 작업은 최대 3회까지 복구하고 수동 재시도는 별도로 허용한다. 제공자 응답 직후 저장 전에 프로세스가 종료되는 경우에는 외부 호출의 정확히 한 번 실행을 보장할 수 없다.

이 작업자는 현재 `next dev` / `next start` 또는 OCI 같은 지속 실행 Node 환경을 전제로 한다. 요청 종료 후 프로세스가 정지하는 서버리스 호스팅에서는 별도 상시 작업자로 분리해야 한다.

같은 취약점의 코드·주변 문맥·규칙 설명·프롬프트 버전·모델이 같으면 저장된 수정안을 재사용한다. 모델 변경만으로 기존 수정안을 자동 재생성하지 않으며 사용자가 선택한 모델로 다시 생성할 수 있다. 의존성은 공지와 OSV/NVD 검증을 우선하고 근거가 부족할 때만 AI를 호출한다.

새 검사부터 탐지 구간 위아래 5줄을 함께 저장한다. 문맥은 최대 120줄·12,000자로 제한한다. 상세 화면 위에는 원본과 탐지 위치, 아래에는 변경 비교를 표시한다. 삭제한 줄은 빨강과 −, 추가한 줄은 초록과 +로 구분하고 원본·수정본 줄 번호를 함께 표시한다. 이전 검사에 문맥이 없으면 재검사 안내를 표시한다. 결과는 수정 제안이며 실제 코드 적용이나 취약점 해결 처리를 자동으로 하지 않는다.

기존 DB 갱신: `npm run db:init`, 설명 문구 갱신: `npm run db:sync-rule-copy`. 두 작업 모두 이력을 삭제하지 않는다.

`npm run test:code-review`는 문맥 범위, 줄 변경 비교의 원본 복원, 점수 경계, 코드 이스케이프와 화면 순서를 확인한다.

신규 MD5·TLS 샘플은 `description_source=semgrep`으로 저장하여 Semgrep 탐지 원문만 표시한다. 별도 작성한 영향·해결 설명을 덧붙이지 않는다. 상세 창은 등급과 닫기 버튼이 있는 헤더를 스크롤 영역 밖에 두므로 내용을 내려도 X 버튼이 유지된다.

기존 결과의 제목만 갱신하려면 `npm run db:sync-rule-titles`를 실행한다. 삭제된 SQL·경로 조작·HTML 샘플의 과거 결과에도 적용하며, 본문·원문 출처·위험도·처리 상태는 바꾸지 않는다.

의존성 제목은 패키지명·설치 버전을 유지하고 보안 공지의 문제 유형을 짧은 한국어로 표시한다. 예: `next@16.3.7 · 외부 요청으로 서버 코드 실행 가능`. 확인하지 못한 유형은 원래 제목을 길이만 제한해 보존하며, 공지 본문은 바꾸지 않는다. 제목 갱신 명령은 기존 영문 의존성 제목에도 같은 형식을 적용한다.
